1. Summary

The PUU Monitoring module was developed against the development database. Moving to production requires four things: two configuration tables, two indexes on existing log tables, five permission rows with their role grants, and six configuration rows.

No existing table is altered and no column is added to any existing table. The module adds no domain tables and never writes application data. Both SLA clocks and the entire movement tracker are derived from tbl_application_status_logs, which NILAM already writes on every status transition. The two new tables hold configuration only.

Why the sidebar menu is currently invisible

The sidebar wraps the whole section in a permission gate (resources/views/layouts/sidebar.blade.php):

@if(Auth::user()->hasAnyPermission(['view_selfmonitorings', 'view_assignmentmonitorings', 'view_managementmonitorings']))
{!! Menu::puumonitoring() !!}
@endif

With none of those permissions present, the gate is false and the entire section is hidden — including the ungated Work Monitoring link inside the macro. hasAnyPermission() returns false for a non-existent permission rather than raising an error, which is why the application behaves normally instead of failing.

3. Objects to Create

3.1 Table — tbl_puu_sla_configs

SLA thresholds and RAG bands. Editable by PUU without a deploy, because statutory timelines change. Every day count stored here is a working day; Saturday and Sunday are never counted.

CREATE TABLE IF NOT EXISTS `tbl_puu_sla_configs` (
    `id`         BIGINT(20) UNSIGNED  NOT NULL AUTO_INCREMENT,
    `key`        VARCHAR(50)          NOT NULL,
    `value`      SMALLINT(5) UNSIGNED NOT NULL,
    `label`      VARCHAR(150)         NOT NULL,
    `updated_by` BIGINT(20) UNSIGNED      NULL DEFAULT NULL,
    `created_at` TIMESTAMP                NULL DEFAULT NULL,
    `updated_at` TIMESTAMP                NULL DEFAULT NULL,
    PRIMARY KEY (`id`),
    UNIQUE KEY `tbl_puu_sla_configs_key_unique` (`key`),
    KEY `tbl_puu_sla_configs_updated_by_foreign` (`updated_by`),
    CONSTRAINT `tbl_puu_sla_configs_updated_by_foreign`
        FOREIGN KEY (`updated_by`) REFERENCES `tbl_users` (`id`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COLLATE = utf8mb4_unicode_ci;

3.2 Table — tbl_puu_holidays

Non-working days beyond the weekend. Weekends are excluded by rule rather than by row, so this table holds public and state holidays only. While it is empty, festive periods count as working days.

CREATE TABLE IF NOT EXISTS `tbl_puu_holidays` (
    `id`           BIGINT(20) UNSIGNED NOT NULL AUTO_INCREMENT,
    `holiday_date` DATE                NOT NULL,
    `label`        VARCHAR(150)        NOT NULL,
    `created_at`   TIMESTAMP               NULL DEFAULT NULL,
    `updated_at`   TIMESTAMP               NULL DEFAULT NULL,
    PRIMARY KEY (`id`),
    UNIQUE KEY `tbl_puu_holidays_holiday_date_unique` (`holiday_date`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COLLATE = utf8mb4_unicode_ci;

3.3 Indexes on existing log tables

Every dashboard load resolves SLA clocks by walking a document's history, filtered by (application_id, status, created_at). These are additive and non-blocking at the current table sizes. Nothing else about these tables is changed.

CREATE INDEX IF NOT EXISTS `tbl_asl_cycle_idx`
    ON `tbl_application_status_logs` (`application_id`, `application_status_id`, `created_at`);

CREATE INDEX IF NOT EXISTS `tbl_adsl_cycle_idx`
    ON `tbl_application_document_status_logs` (`application_id`, `document_status_id`, `created_at`);

Six rows seeded into tbl_puu_sla_configs. All values are working days.

Optional — fixed-date public holidays

The --holidays flag additionally seeds five fixed-date federal holidays for 2025, 2026 and 2027 (15 rows): New Year's Day (01-01), Labour Day (05-01), National Day (08-31), Malaysia Day (09-16) and Christmas Day (12-25).

The moving holidays are deliberately not seeded. Hari Raya Aidilfitri, Hari Raya Aidiladha, Awal Muharram, Maulidur Rasul, Nuzul Al-Quran, Chinese New Year, Thaipusam, Wesak, Deepavali and the Agong's birthday follow lunar and gazetted calendars that shift every year. They must be added per year from the gazette. A subtly wrong statutory calendar silently corrupts every SLA figure, which is worse than a visibly incomplete one.

6. Install Procedure

Order matters — the schema must exist before the seeder runs.

# Step 1 - schema (tables + indexes). Every statement is IF NOT EXISTS, safe to re-run.
mysql -h antartika.uitm.edu.my -u effendy -p nilams < database/sql/puu_monitoring_install.sql

# Step 2 - preview the permission and configuration seeding, writing nothing
php artisan puu:install --dry-run

# Step 3 - apply
php artisan puu:install

# Step 3a - optionally include the fixed-date holidays
php artisan puu:install --holidays

7. Verification

SHOW TABLES LIKE 'tbl_puu_%';
-- expect: tbl_puu_holidays, tbl_puu_sla_configs

SHOW INDEX FROM tbl_application_status_logs          WHERE Key_name = 'tbl_asl_cycle_idx';
SHOW INDEX FROM tbl_application_document_status_logs WHERE Key_name = 'tbl_adsl_cycle_idx';

SELECT `key`, `value` FROM tbl_puu_sla_configs ORDER BY `key`;
-- expect 6 rows

SELECT name FROM tbl_permissions
WHERE name IN ('view_selfmonitorings','view_assignmentmonitorings',
               'view_managementmonitorings','view_puureports','export_puureports');
-- expect 5 rows
Run these rather than assuming success. PuuSlaConfig carries a DEFAULTS fallback so the module degrades to sane behaviour on a half-migrated environment instead of throwing — which means a missing table fails quietly.

8. Sequencing Risk

The sidebar menu becomes visible the moment the permissions exist. Every Admin, Assistant Superadmin, Legal Advisor and Drafter/Vetter on production will see PUU Monitoring in their sidebar. If the module's application code has not been deployed yet, those links resolve to routes that do not exist and the users get 404s.

Recommended order:

  1. Deploy the module's application code to production.
  2. Apply the schema (Step 1).
  3. Run the seeder (Steps 2–3).
  4. Verify (Section 7), then confirm the menu renders for one user of each role.

9. Rollback

DROP TABLE IF EXISTS `tbl_puu_sla_configs`;
DROP TABLE IF EXISTS `tbl_puu_holidays`;
DROP INDEX `tbl_asl_cycle_idx`  ON `tbl_application_status_logs`;
DROP INDEX `tbl_adsl_cycle_idx` ON `tbl_application_document_status_logs`;

Dropping these removes the module's configuration only. No application data is touched, because the module never writes any. To hide the menu without dropping anything, revoke the permissions from the roles — the sidebar gate then evaluates false again.

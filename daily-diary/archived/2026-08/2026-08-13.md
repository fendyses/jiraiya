## 2026-08-13 (Night - 12:38 AM) - PUU Monitoring UX Completion and Operational Clarity

### Session Summary
- **Type**: Full-stack enhancement and UI/UX refinement
- **Focus**: Complete the Nilam PUU Monitoring experience across Management, My Performance, Work Monitoring, individual reports, document tracking, periodic reports and Excel exports.
- **Outcome**: PUU Monitoring now has consistent two-stage infographics, precise operational labels, distinct status colours, shared explanations, actionable missing-data diagnostics and filtered Excel export. All work remains uncommitted.

### Main Topics Discussed
1. **Unified monitoring experience**
   - Combined My Performance and Assignment SLA into one My Performance page, with Assignment Performance presented first as Stage 1 and Vetting/Feedback as Stage 2.
   - Refined both stages with workflow infographics, SLA rings, workload indicators and clearer operational hierarchy.
   - Rebuilt Management Monitoring as a modern infographic dashboard with received-date filtering, interactive charts, assignment ownership and officer workload cards.

2. **UiTM officer profile photos**
   - Integrated staff photos through the configured UiTM profile-photo API using staff usernames/IDs.
   - Kept the API credential server-side behind a permission-protected signed photo proxy.
   - Added photos consistently to Drafter/Vetter and Assignment Ownership cards, with safe initials fallbacks.

3. **Clear missing-clock terminology**
   - Replaced the ambiguous “No clock” label throughout PUU Monitoring with two operational states:
     - **No Drafter/Vetter** — no officer has been assigned.
     - **Status Missing** — an officer exists, but required status history is unavailable.
   - Standardised the terminology in dashboards, queue cards, tables, legends, individual reports, document tracking, periodic reports and Excel output.
   - Introduced distinct colours across all views: muted blue for No Drafter/Vetter and purple for Status Missing.

4. **Shared status guidance and drill-downs**
   - Added a reusable “What do these statuses mean?” explanation using live configured thresholds.
   - The guide explains On track, Due soon/Watch, At risk, No Drafter/Vetter and Status Missing; it stays expanded on user reports and is collapsible elsewhere.
   - Made management metrics and charts drill into the exact Work Monitoring records while preserving reporting dates.
   - Added dedicated Stage 1/Stage 2 breach, abandonment, pending and missing-status filters, with bookmarkable URLs.

5. **Actionable Status Missing diagnostics**
   - Enhanced the shared SLA view-model to identify the specific missing data:
     - No status history recorded.
     - Vetting clock-start status missing.
     - Assignment status log missing.
     - Received and creation dates missing.
   - Displayed these hints in Work Monitoring, shared document/assignment cards, individual reports, periodic reports and document tracking.

6. **Filtered Work Monitoring export and report download fix**
   - Fixed the endless full-page loader after XLSX generation by exempting download buttons from the global navigation preloader.
   - Added **Export current view** to Work Monitoring.
   - The export reproduces the active received-date range, operational filter, DataTables search phrase, selected column and sort direction.
   - Added a Status Missing Detail column with separate Stage 1 and Stage 2 diagnoses.

### Key Insights & Learning
- A successful file response does not trigger a replacement page load, so a global submit preloader must explicitly distinguish downloads from navigation.
- “No clock” combined two very different operational conditions; splitting the states improves both accountability and data cleanup.
- Status colour should communicate meaning consistently across badges, cards, filters and charts, while text and icons retain accessibility beyond colour alone.
- Stage 1 and Stage 2 risks must remain separate in both metrics and drill-down filters because one document can carry different states in each clock.
- Shared Blade partials and view-model diagnostics prevent terminology and threshold explanations from drifting between pages.

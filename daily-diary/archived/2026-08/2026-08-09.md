### Key Insights & Learning

- **The status column is destructive.** An `ApplicationStatusLog::created` boot hook rewrites `applications.application_status_id` on every transition. 19 applications currently show "Executed Document"; **143 have ever reached it**. The naive `!= 19` query misclassifies ~124 executed documents as outstanding. Everything must be resolved from history.
- **Literal "not yet executed" is useless**: 1,383 of 1,402 rows, 524 of them terminal. The honest in-flight number is **853**.
- **Guessed slugs fail silently.** Four of five terminal slugs I wrote didn't exist — status 1 "Application Withdrawn" has the slug `new`. `whereIn` just matched fewer rows and inflated Outstanding by 28. Added a `Log::warning` guard and a `puu:verify` check.
- **The data is starkly bimodal.** Closed vetting cycles: median **0** working days (52% finish same day, raw gaps of 2 minutes to 9 hours). Open cycles: median **1,043** working days, 70 of 74 running since 2022. Those aren't late — they're abandoned. Split "breached" from "abandoned" (>90 wd, excluded from averages): breached went 99 → 10 and team SLA health 68% → 98.6%. Without the split, compliance is permanently pinned low by 2022 records.
- **Dual-role users broke the RBAC assumption.** I had written "nobody holds both tiers." Wrong: **292 users hold >1 role and 7 of 13 vetters also hold Admin.** They would have opened "My Performance" and seen all 1,402 documents under a heading saying "assigned to me". Fixed with intent-based scoping (`visibleTo($user, $selfOnly)`).
- **Accountability isn't the role.** 8 people have assigned vetters but only 4 hold Legal Advisor — and one person did 731 of 789. Grouping had to follow who actually acted.
- **Cross-stage reconciliation caught a real bug.** Stage 1 said 81 awaiting, stage 2 said 64 not-started. The 17-document gap: `assigned_to` set with no status-4 log, so the assignment clock would tick forever on work already assigned. Now `unmeasurable`; both stages agree at 64, and the reconciliation is a permanent check.
- **Two units of "day" silently disagreed.** `working_days` counted date boundaries, `calendar_days` used `diffInDays` (24h periods), so a 21-hour overnight gap rendered "1 working day · 0 cal" on 94 of 853 documents. Both now count boundaries.
- **Blade indentation cost 65% of a page.** Work Monitoring was 2,082,831 bytes; tightening the row markup cut it to 724,276 with identical output. Also found `deferRender: true` was a no-op on a DOM-sourced table and removed it.

## 2026-08-09 (Late Night - 1:15 AM) - PUU Individual User Report and Print-Safe Visuals

### Session Summary
- Type: Full-stack enhancement + PDF/print debugging
- Repo: Nilam (`/Applications/Sites/nilam`), branch `development`
- Focus: Add drill-down user reports from PUU Management, profile photos, date filtering, and a reliable Save as PDF layout
- Outcome: Individual reports are working with interactive screen charts and server-rendered print graphics that preserve the original radial, donut, and grouped-bar chart types. Uncommitted.

### Main Topics Discussed

1. **Management-to-user drill-down.** Each person in `/puu_monitoring/management` now links to `/puu_monitoring/user/{id}`. The report combines that user's assignment-owner and vetter activity, with KPI cards, SLA panels, document tables, and visual summaries.

2. **Secure UiTM profile photos.** The report uses `tbl_users.username` to request the UiTM photo API through a signed, permission-protected Laravel proxy. The bearer token remains server-side in `.env`; responses are MIME-validated and cached for one day.

3. **Date filtering.** Added optional inclusive Received From / Received To filters based on the application's received date. Every KPI, chart, SLA panel, and table recalculates for the selected period, while a valid user with no results still receives an empty report instead of a 404.

4. **Save as PDF layout.** Added an A4 landscape print composition with four KPI columns, three chart columns, paired stage panels and document tables, deliberate page breaks, print-only hiding of navigation controls, and a document title that produces `<User Name>-PUU_Report.pdf` in the browser save dialog.

5. **Invisible chart investigation.** Browser-generated ApexCharts SVG did not survive the real print pipeline consistently, and image snapshot attempts remained unreliable. Replaced only the print representation with inline server-rendered SVG while keeping ApexCharts interactive on screen.

6. **Original chart types preserved.** The final PDF keeps the report's visual language: concentric radial rings for SLA compliance, a segmented donut for queue health, and grouped horizontal bars for stage comparison. The static SVG blocks are siblings of the Apex targets so Apex cannot erase them during initialization.

### Key Insights & Learning

- Printing a page is a separate rendering environment: a chart visible in the browser can disappear in Chrome's print compositor even when its live SVG exists in the DOM.
- Server-rendered inline SVG is the dependable print fallback because it exists in the initial HTML and has no dependency on animation timing, canvas conversion, or `beforeprint` JavaScript.
- Screen and print can use different renderers without changing the information design. ApexCharts remains the better interactive renderer; deterministic SVG is the better PDF renderer.
- User existence must be established before applying a date filter, otherwise a legitimate zero-result period can be mistaken for an invalid user report.
- Native browser printing controls page contents but not Chrome's optional header/footer setting; users may still need to disable browser headers and footers in the print dialog.

### Collaboration Highlights

Fendy repeatedly tested the real Save as PDF path and reported that every graph was still missing. That feedback exposed a gap that HTML rendering and automated checks alone did not reveal. He also caught an unwanted chart-type change in an intermediate print fallback, leading to the final implementation that preserves the original radial, donut, and grouped-bar visuals.

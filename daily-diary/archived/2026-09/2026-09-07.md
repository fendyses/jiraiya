### Main Topics Discussed

   - Final Draft (app 9 / doc 5) — **Legal Advisor** clicks "Endorse Document" (`AmendmentController@approve`)
   - Only `meu_approval=1` reaches Final Draft; the other two endorse options skip straight to `pending-signed-document`
   - Letter date = endorsement date (`ApplicationController.php:415`), falls back to vetted-draft precisely because of those bypass paths

Its MEU variant's button is commented out in `assigns/show.blade.php:295-303`, but the route stays reachable.

4. **"Hairina made the Final Draft?"** — She didn't. The page has **two** tables both containing "Final Draft" rows: `application_status_logs` and `application_document_status_logs`. She appears only in the second.

### Key Insights & Learning

**The root cause, in full:**

Before Oct 2025, `MeuApprovalController@approve()` was ~20 lines and never touched document status at all. Commit **`d199f6b` (2025-10-08)** — a 1,010-insertion, 20-file commit — grew it to ~170 lines and added document-status tracking through the LPU stage. It referenced three new slugs:

| Slug | Seeded? |
|---|---|
| `not-approved-by-meu` | never |
| `document-for-lpu-notified` | never |
| `document-for-lpu-approval` | never |

**Zero files under `database/` in that commit.** The code half of the feature shipped; the data half never did. Understandable — migrations hadn't run since 2022-11-01, so there was no habit of shipping reference data alongside code.

**Why it stayed silent for 11 months** — the same commit added crash-prevention guards, but handled the misses two different ways:
- `if($document_status) { ... }` → skip the write (harmless)
- `if(!$document_status) { $document_status = ...'final-draft'; }` → **substitute a neighbour (harmful)**

A guard written to stop a 500 error converted a hard failure into plausible-looking wrong data. And `final-draft` was a *believable* wrong answer — at that point the document genuinely is a final draft. Nobody questions a label that makes sense.

First bad row: **2025-10-10 16:10:13**, two days after the commit. Then 512 more.

**Why it surfaced now** — not because the label was wrong, but because of *who* it was attached to. The log stamps `created_by` from the session, so the row carried Hairina's name, and the view renders it as "Created by HAIRINA on 05/08/2026" against "Final Draft" — a Legal Advisor action. A role that couldn't have done it appeared to have done it. The label alone was invisible for 11 months; the **name** made it legible in one glance.

**The lucky asymmetry** — in the same block the *application*-status miss fails loudly (`return redirect()->back()->with('error', ...)`). Almost certainly unintentional, but it's why this stayed cosmetic. The field driving routing/queues/permissions had a loud guard; the field driving labels had a quiet one. Reversed, it would have been 512 mis-routed applications instead of 512 mislabelled rows.

### Work Done — Code-Only Fix (no DB writes, no new columns, no new rows)

1. `app/Application.php` — 3 constants + `resolveDocumentStatusName()` / `documentStatusLabel()` read-time resolver. Relabels only when doc=5 AND a `submit-for-lpu-notified` app-status row exists within 5 seconds.
2. `app/Http/Controllers/MeuApprovalController.php` — removed both silent fallbacks; `$document_status` stays null (existing guards skip the write, restoring pre-`d199f6b` behaviour) + `Log::warning` so the next miss announces itself.
3. `resources/views/applications/show.blade.php:424` and `ptjapplications/show.blade.php:359` — swapped to `documentStatusLabel($status)`.
4. `app/Http/Controllers/ApiController.php` — dashboard timeline modal (was showing "Final Draft" four times for 8329) relabelled through the same resolver.

**Verified against production:** 3,734 applications swept — **512 relabelled, 3,796 genuine endorsements untouched, 0 false positives.**

### Honest Weaknesses Noted
- It **masks rather than fixes** — DB still says "Final Draft"; 6 surfaces for the *current* status still stale (3 dashboard buttons, 3 in `ReportController`)
- Hardcoded ids (5, 12) are brittle if those tables are ever reseeded
- Invents a label string with no row behind it — the same smell as the original bug
- `DOC_LABEL_FIX_DATE = '2026-09-08'` flagged as a **liability**: redundant (the signature is already self-disarming after the controller fix) and risky (deploy slips past the date → silent gap). Recommended removal, not yet applied.

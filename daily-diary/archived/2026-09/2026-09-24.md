## 2026-09-24 (Afternoon - 16:30) - MyStudent: eGL Study-Mode Check + 24h Duplicate-GL Rule

### Session Summary
- Type: Work
- Repo: MyStudent (`/Applications/Sites/mystudentvue`) — UiTM
- Focus: (1) Can full-time extended (SML) students use eGL? (2) Allow regenerating the same GL once the previous one is more than a day old.
- Outcome: (1) Answered: the frontend has no study-mode gate for eGL, and the digitalcampus API decides. (2) Duplicate check in `src/views/kesihatan/GlPage.vue` now blocks only within 24h. Change is **not committed** and not tested in a browser.

### Main Topics Discussed

1. **SML and eGL.** The `/egl` icon in `KesehatanPage.vue` shows for everyone. `GlPage.vue` never reads `studymode_code`; it posts `student_id` to `https://digitalcampus.uitm.edu.my/api/mystudent/generate/gl` and shows the form only if `jumlah kelayakan` > 0 (admins bypass). So SML eligibility lives in the API, not this repo.
2. **Study-mode lists are inconsistent across the app.** Borang Perubatan: `S, SA, SF, SK` (`KesehatanPage.vue:138`). ASNB field: `S, SA, SF, SN, SK, SML` (`ProfilePage.vue:154`, `SponsorPage.vue:406`). eGL: no list. Fendy read the medical-form list as the GL rule; clarified it isn't.
3. **24h duplicate rule.** Old logic permanently blocked a GL matching hospital + jenis + negeri + `jumlah kelayakan` + `baki boleh guna` in `sejarah_gl`. Now it only blocks if a matching entry's `tarikh_jana` is < 24h old. The block message adds "GL baharu boleh dijana semula selepas 24 jam."

### Key Insights & Learning
- 💡 "More than one day" was implemented as a rolling 24 hours, not the next calendar day; offered to switch.
- ⚠️ The check is client-side only. If the digitalcampus API has its own duplicate block, it still applies.
- Entries with a missing/invalid `tarikh_jana` no longer block anything (NaN comparison is false).

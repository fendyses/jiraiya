## 2026-07-31 (Afternoon - 4:41 PM) - MyStudent Medical Form Token-Renewal Fix

### Session Summary
- Type: Bug diagnosis and corrective implementation
- Focus: `/kesihatan/medical-form` — some students renewed an expired upload token and still hit the "token expired" popup on Hantar Borang
- Outcome: Root cause pinned to a too-short client poll window; fixed in `MedicalForm.vue`, verified by recheck, left staged uncommitted for Fendy

### Main Topics Discussed
1. Explored `MedicalForm.vue` end-to-end: the token-expired modal, `refreshToken()`'s Cloud-Function-trigger-and-poll flow, and `confirmSubmit()`'s pre-upload freshness re-check — no stale-closure bug found, token is a single reactive `this.token` read fresh everywhere.
2. Reviewed prior git history on this file (`a66be06`, `bd3c586`, `54b77de`) showing this exact flow had already been iterated on three times — a known recurring pain point.
3. Fendy supplied a real failing case: student 2026541495, who renewed and still saw the popup. Wrote a throwaway diagnostic script against the live Firestore client SDK to inspect her actual `token_mystudent` and `mystudentlog` docs.
4. Data showed her token was in fact valid — `exp` was exactly 14 days after `mystudentlog.loggedAt` — proving the mint itself worked. This reframed the bug from "renewal fails" to "renewal times out client-side before it finishes."
5. Diagnosed that `refreshToken()` only polled Firestore for 25 seconds while the Cloud Function mint (cold start + a real UiTM login call) can take longer, especially under load — timing out the student back into "expired" even though the token often finished minting moments later in the background.
6. Implemented the fix: split `refreshToken()` into a trigger step plus a new `pollForFreshToken()` method polling for up to 5 minutes (1.5s interval for the first minute, then 5s), added `beforeUnmount` cleanup via a `_tokenPollCancelled` flag, and tightened the new-token validity check to require an actual expiry rather than treating a missing one as automatically valid.
7. Also hardened `confirmSubmit()`'s pre-upload freshness check, which previously swallowed *any* read error as "offline" and silently proceeded with a possibly-stale token — now it only does that for genuine connectivity errors (`navigator.onLine` false, or Firestore codes `unavailable`/`deadline-exceeded`/`cancelled`), otherwise it stops and asks the student to retry.
8. Self-reviewed the diff on request and caught a real UX bug in the fix itself: the new "server's slower than usual, please wait" notice was reusing the red `.error-msg` style, which would have made the wait look like a failure. Split it into a separate `tokenRefreshNotice` field with a new neutral `.info-msg` style.

### Key Insights & Learning
- A recurring "token expired" complaint after three prior patches was not another instance of the same stale-cache bug — it was a genuinely new failure mode (client timeout racing a slow server-side mint), only visible once real production Firestore data was pulled for the specific affected student.
- When a fix widens a wait/retry window, the accompanying "please wait" messaging needs its own visual language — reusing error styling for a non-error state can undo the UX benefit of the fix.
- Committed to the repo's existing precedent of a checked-in `check-student.js` ad hoc diagnostic script; used the same live client Firebase config to pull one student's docs rather than guessing at server-side behavior that lives outside this repo (the Cloud Function itself isn't checked out locally).

### Collaboration Highlights
- Fendy asked for a recommendation rather than an immediate fix, then supplied a concrete failing student ID that made the diagnosis conclusive instead of speculative.
- Fendy explicitly asked for a recheck after implementation, which caught the `.error-msg`/`.info-msg` styling bug before it shipped.

### Growth and Development Notes

- Practiced a genuine self-review pass rather than a rubber-stamp recheck: re-read the full diff, reasoned about Vue 3 reactivity implications of ad hoc instance flags, and checked CSS styling implications of a new UI state.

### Memorable Moments

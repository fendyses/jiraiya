### Session Summary

### Main Topics Discussed
1. **Which letter is which** — untangled three different letters for an application:
   - `/vettings/letter/{id}` = LA's "Submit for Endorsement" **form** (used *during* checking), NOT downloadable output.
   - MEU/LPU approval letters = stored HTML (`meu_letter`/`lpu_letter`), downloaded via `myapplications/approval` & `myapplications/lpuapproval`.
   - **JUU endorsement letter** ("Kelulusan PUU", the sample) = `myapplications/final_draft.blade.php`, produced by `MyApplicationController@finalDraft` → `certificate_final_draft.pdf`. This is the one matching the user's sample ("…telah disemak dan diperakui oleh Jabatan Undang-Undang (JUU) Universiti untuk dibawa ke Mesyuarat MEU").
2. **Built the admin download** reusing the existing JUU template:
   - `ApplicationController@juuLetter()` — gated by `view_applications`, date from `final-draft` (fallback `vetted-draft`) status log, letterhead slug `certificate`, downloads `surat_kelulusan_juu_<id>.pdf`. Redirects with a message if not yet endorsed.
   - Route `GET applications/juuletter/{application}` (placed BEFORE the `applications` resource route to avoid the `{application}` wildcard swallowing it).
   - Button "JUU Approval Letter: Download" (blue `btn-primary`) as a row under **Vetter/Drafter Name** in `applications/show.blade.php`.
3. **How applicants originally get it** — self-service: My Applications → row dropdown → "Final Draft Certificate" (`myapplications/finaldraft/{id}`), owner-only (`authorize('update')`). Email notifications (`ApplicationCreated@toMail`) only send a "View Details" link, not the PDF attachment.

### Key Insights & Learning
- **Local vs production rendering trap.** Local preview looked broken (big X box + garbled/letter-spaced text). Causes were all local-only: (a) letterhead image lives only on the prod server, (b) `ms_MY` Malay locale not installed locally, (c) dompdf can't embed **Arial** locally.
- **Don't "fix" the font.** I temporarily swapped Arial→DejaVu to make local render clean — but extracting fonts from the real sample PDF showed the official letter is **ArialMT / Arial-BoldMT at 16pt & 18pt**, which the original template already used correctly. Reverted to keep production fidelity. Lesson: verify against the *real* artifact before changing a shared template; local rendering gaps are not production bugs.
- Removed an over-fragile guard in the controller that redirected to `/applications` whenever the Malay locale was missing — that was why the button "did nothing" on the locale-less local box. Now best-effort locale + always download.
- Tooling note on this Mac: `pdftoppm`/ghostscript are broken under ServBay; **PyMuPDF (`fitz`)** works for rendering PDFs to PNG, and `qlmanage -t` gives quick thumbnails.

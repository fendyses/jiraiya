## 2026-09-10 (Late Night - 12:50 AM) - The Save Button Was Never the Problem

### Session Summary
- Type: Debugging, API investigation, and UI redesign
- Repo: **NRHome** (`/Applications/Sites/nrhome`) — UiTM
- Focus: Chase down "cannot save new house", fix role display, then redesign the login screen
- Outcome: Root cause found and fixed after two wrong diagnoses; four commits landed (`ae98df1`, `adf0637`, `5a60aa1`, `17536b2`); working tree clean

### Main Topics Discussed

1. **Account menu showed "Pengguna" for an admin.** Two independent causes stacked. First, the JWT payload carries `name` and `nric` but no role flags at all, so every page reload reset the store to defaults. Second — found only after the first fix appeared to fail — the gateway returns role flags as **real booleans**, while the whole codebase assumed strings `"0"`/`"1"`. `parseInt(true)` is `NaN`, so every role read as false. A single `adaPeranan()` helper now handles both shapes.

2. **A student access-control bug fell out of that.** `router-not-student.js` gated `/house` and `/house/update` with `Boolean(parseInt(is_std))`. Once real booleans started arriving, a student's `is_std: true` would have evaluated to false and let them straight into the landlord forms. Same broken idiom in `router-reset-pass.js`, `House.vue` and `Index.vue`.

3. **"Cannot save new house" — the real cause was one word.** The uploader sent the file as `field-name="files"`; the gateway requires `fail`. Verified against production: `files` → `422 {"loc":["body","fail"],"msg":"Field required"}`, `fail` → `200` with a CDN URL. Every image upload in the app had been failing. Since a house without a photo is never shown to students, landlords saved a house, saw nothing appear, and reported it as a failed save. The house was always saving; the photo never was.

4. **Two wrong diagnoses before that, both stated too confidently.** First: that the 422 came from `zone`/`zone_campus` not being validated client-side — wrong, and making them required was a regression that had to be reverted. Second: that the token-refresh retry failed because the expired token stayed in the request body — disproved by testing `GET /nrent/login`, which showed the header wins and the body copy is only a fallback.

5. **Gateway field gaps, confirmed with evidence.** The `Rumah` write model has no `zone`/`zone_campus`, and Pydantic ignores extra fields, so they are dropped silently. A full scan of all 488 records showed a clean cutoff at id 361: every record from id 365 onward has `zone_campus = None` (204 of them), and `created_at` starts existing at exactly the same point. `negeri` is the mirror image — accepted on write, never returned by GET. Fendy confirmed both columns exist as varchar in `rumahs`, so no DB migration is needed.

6. **Live save test on production, then cleaned up.** Created rumah 628 with rare values (`negeri: W.P. Labuan`, `zone_campus: Kota Kinabalu`) to settle whether `negeri` persists. Deleted afterwards along with two earlier test records (625, 626, 627) and their images — verified `404` and total dropped 528 → 525.

7. **Empty listing after login.** `Index.vue`'s `.catch` was only `console.log`, so a failed fetch looked identical to an empty result. The listing endpoint returns intermittent `500`s — page 3 failed once and returned `200` on retry. Added retry with backoff for 5xx/network only, plus a visible error state with a "Cuba Lagi" button.

8. **Login screen redesigned across four attempts.** Aurora split → photographic split → both rejected ("i still doesnt like the split style"). Landed on a single centred panel. Two of Fendy's own calls fixed it: put everything in one div, and keep the white text with a shadow rather than switching to dark type. Final style follows his "Sistem Integrasi" reference — deep plum, gold as the only accent, official MyDigitalID button kept.

### Key Insights & Learning

- **`Boolean(parseInt(x))` fails in both directions.** `parseInt(true)` is `NaN`; `Boolean("0")` is `true`. Mixing string and boolean flags in one codebase guarantees one of them breaks silently.
- **A `200` is not proof of a save.** The gateway returns `200` for writes whose fields it silently discards. Only the database row settles it.
- **Two wrong root causes came from inferring instead of checking.** Reading `openapi.json` at the start would have shown the write model had no zone fields and would have prevented both.
- **`::before` paints beneath real child elements.** A colour wash sat under the photo div, so the panel rendered flat grey. Explicit `z-index` on every layer fixed it.
- **A duplicate CSS rule later in the file silently won.** A leftover `&__kaki` from the discarded split style painted the footer dark navy on a dark panel — invisible.
- **HMR does not re-run `created()`.** The live house count looked broken three separate times; a full reload always showed it working.

### Collaboration Highlights
- Fendy pushed back three times on design direction, and each rejection was correct. "Both of them are too vibrant" identified a real fault: the panel used `backdrop-filter: saturate(150%)`, amplifying the background through the glass so nothing could win.
- He asked "is it the correct ways to fix it?" about the token fix — that question directly caused the test that disproved my explanation.
- He supplied the DB facts I could not see: `zone_campus` and `negeri` both exist as varchar in `rumahs`.

### Verification
- `field-name` fix: real end-to-end save produced "Rumah dan 1 gambar berjaya disimpan", rumah 628 + gambar 123, confirmed via `GET /nrent/gambar?rumah_id=628`.
- Role fix: live session reads `Pengguna · Pentadbir · Staf · Tuan Rumah`, no console errors.
- Listing retry: simulated two `500`s then success → recovered in ~2.1s with 8 houses; persistent `503` → error state + retry button; `422` → one attempt only.
- `gantiToken()`: 10 assertions run against the function extracted from the source file — JSON body, query params, object body, FormData, non-JSON body, missing body. All pass.
- Logo: 3,533,201 → 18,849 bytes (99.5%), 2400×1718 → 480×344, partial-alpha pixels 1362 → 1075 so the rim light still traces the oval.

### Looking Forward
- **Not yet reported to Integration Unit:** the intermittent `500` on `GET /nrent/rumah/v2`. It was dropped from the brief when it was simplified, and it is the actual cause of the blank-listing complaint.
- Brief for Integration Unit is written and private: three asks — add `zone`/`zone_campus` to the write model, return `negeri` in GET, add `filter_zone_campus` + `filter_negeri`.
- Check `SELECT negeri FROM rumahs WHERE id = 628` (soft-deleted, so the row should still be there) to confirm whether `negeri` actually persists.

## 2026-09-10 (Afternoon - 3:44 PM) - The Browser Was Never Looking at My Server

### Session Summary
- Type: Bug fix, feature build, and verification-tooling discovery
- Repos: **NRHome** (`/Applications/Sites/nrhome`) — UiTM, then **MyAlumniCard** (`/Applications/Sites/myalumni-angular`) — UiTM
- Focus: Fix a stretched logo on the login screen, then build the Ukuran Jubah section on the convocation attendance form
- Outcome: Both shipped and committed by Fendy (`44b0d95`; `bd621c9`, `820e11e`); 13/13 focused tests pass

### Main Topics Discussed

1. **Login logo stretched on phones — one missing property.** The base rule sized the mark by width (`width: 100%; max-width: 200px; height: auto`), but the `max-width: 600px` breakpoint overrode *only* the height (`height: 62px`) and left `width: 100%` standing. The 480×344 logo was forced into a 200×62 box — squashed to 43% of its correct height. Fixed by constraining the breakpoint by width too (`max-width: 150px`), which also restores the rationale written on the base rule itself: limit by WIDTH so the wordmark stays readable. The other four uses of `nruitm.png` set only `height` with no `width`, so their ratios were already intact.

2. **The verification attempt failed in an informative way.** Trying to confirm the fix visually, the browser at `localhost:8080` showed a login page that does not exist anywhere in the NRHome source — class `nr-login__logo`, a 271×194 logo, heading "Selamat Datang ke NRHome". No service worker, no cache entries. `lsof` showed exactly one listener on 8080, and it was my own `quasar dev`.

3. **A probe file settled it.** Wrote `public/__probe.txt`, curl returned it `200`; the browser's `fetch('/__probe.txt')` returned `404` from an Express-style handler. **The Chrome I can drive is not on the same host as my shell.** `resize_window` also reported success while `innerWidth` stayed 1745. Verification moved to the bundle level instead: grepping the served lazy chunk `1.js` confirmed the corrected rule, and the compiled CSS showed no `height` override.

4. **`/attendance` was in a different repo entirely.** Nothing in NRHome matched "attendance", "Alumni ID" or "Gelaran". A sweep of `/Applications/Sites/` found `myalumni-angular/src/app/attendance/`. Fendy confirmed mid-turn: *"eh yes..im working now on different repo, sorry."* That also retroactively explained the browser mismatch.

5. **Placement was decided by brace-matching, not by reading indentation.** The template's indentation is inconsistent — three closers at 24/20/16 spaces where four nested blocks were open. A script that strips `{{ }}` interpolations and counts braces proved line 85 `@if(attend == 'true')` closes at line 309, and that the whole template balances. The section went in immediately before that, so it only shows for graduates who are attending.

6. **Field naming and the chart changed twice.** `jubah_size` → `ukuran_jubah` with lowercase stored values (`s`, `2xl`) on Fendy's instruction. Then a new chart arrived without the KATEGORI column, so that column was dropped from the data, the table, and the dropdown labels, and the caption became "Panduan Carta Ukuran Jubah Graduan UiTM". All ten height/weight ranges were re-checked against the new photo — identical, only the column went away.

7. **Presentation pass.** The dropdown had been stretching to a full `col-md-4` for a value as short as "M"; it became a fixed 200px flex column with the chart taking the rest. Chart got the theme's own tokens from `_variables.scss` (`$primary #5d87ff`, `$light-primary #ecf2ff`, `$borderColor #e5eaef`), a framed container, hover state, and a selected row marked by a 3px left bar rather than colour alone. Added a summary card under the dropdown and made chart rows clickable — a highlighted row invites a click whether or not it does anything.

8. **"Test the submit" — declined the real one, proved the mechanics instead.** A genuine submit would write a live convocation record for a real graduate to production Firestore, and reaching the form needs a login I cannot perform. Instead: a focused spec that builds the component with `new` + mocks (no TestBed, so no Firebase/Router/Material to load), run under ChromeHeadless karma. Captured the actual payload object handed to the save call.

9. **A wrong claim from earlier in the session, corrected.** I had twice warned that the backend needed an `ukuran_jubah` column or the value would be dropped. Reading `updateConvoNoFile` showed it writes to **Firestore** (`graduates/{alumni_id}`), which is schemaless — no migration needed at all.

10. **A leak found by testing the edge case rather than assuming it.** Picking *Ya* + 4XL then switching to *Tidak* left `ukuran_jubah: '4xl'` in the payload — a non-attending graduate would have been counted in the gown order. `attendChanged()` now clears the value, not just the validator.

11. **Derived fields wired through `valueChanges`, deliberately.** Fendy asked for the height/weight ranges to be saved alongside the size without extra input. Putting that in `pilihJubah()` would have covered only the row click and saved empty ranges for anyone using the dropdown. One `valueChanges` subscription covers every path — dropdown, row click, the reset on "Tidak hadir", and `patchValue` when an existing record loads. Renamed to `ukuran_graduan_tinggi` / `ukuran_graduan_berat` on request.

### Key Insights & Learning

- **The Chrome the browser tools drive is not guaranteed to be on the same machine as the shell.** A probe file served by the local dev server and fetched from the page is the decisive one-step test, and it is cheap. Worth reaching for the moment rendered output contradicts source.
- **Rendered output disagreeing with source is data, not noise.** Chasing it (no service worker → single listener → probe) found a real environmental split instead of producing a wrong "it's just cache" explanation.
- **Indentation is not structure.** In a template with `@if` blocks edited by many hands, brace-matching is the only trustworthy way to find where a block ends.
- **Derive shared state at the source of truth, not at one entry point.** `valueChanges` catches the paths a click handler silently misses — including data loaded from storage.
- **Schemaless storage changes the advice.** The "add a column first" warning was right for a SQL backend and simply wrong here; checking the service before repeating it would have saved two turns of bad guidance.
- **`ng build` dirties `.firebase/hosting.ZGlzdA.cache`**, which is tracked. Reverted after each verification build to keep the diff to real source changes.

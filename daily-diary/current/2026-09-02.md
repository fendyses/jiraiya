## 2026-09-02 (Morning - 11:33 AM) - MinIO TLS Diagnostic and the Draft Save Deadlock

### Session Summary
- Type: Work
- Focus: Nilam — diagnosing a MinIO SSL failure, then a cascade of bugs found in the application draft flow
- Outcome: Two commits merged cleanly with five incoming remote commits; a read-only `/minio-check` diagnostic added; nine bugs fixed across the draft, partner, and upload paths

### Main Topics Discussed
1. Started from a `PutObject` failure against `minio.uitm.edu.my:8443` — cURL error 60, self signed certificate in certificate chain. Fendy wanted a retrieve-only link to verify a fix his senior applied, explicitly not an upload link.
2. Inspected the live chain: `*.uitm.edu.my` issued 27 July 2026, chained through SSL.com TLS Issuing RSA CA R1 to the self-signed SSL.com TLS RSA Root CA 2022 — the same reissue behind the 20 August Jawi image incident.
3. Established that no existing Nilam route reliably exercises MinIO: every download path checks local storage first and only falls through to MinIO when the file is absent.
4. Built `/minio-check` as a read-only diagnostic — MinIO health GET, an S3-client HEAD on a key that cannot exist, and outbound letter-image probes with peer certificate issuer and expiry.
5. Fendy ran it and got localhost:9000 output, which correctly identified his machine as local rather than production — the local `.env` carries no `MINIO_*` keys.
6. He then hit "The partners field is required" saving a new application as draft, with the Add Partner button inactive. This turned into the session's real work.
7. Traced a genuine deadlock: validation ran before the `btnDraft` branch, and `#btnPartner` was only enabled by `select2:select`, which never fires when Laravel redisplays the form with `old()` input.
8. Fendy asked the sharpest question of the session — whether resuming a draft would still check partners and the other fields on submit. It exposed that `update()` had no `areas` rule at all and hardcoded `activities` to nullable.
9. Rechecking on request surfaced three more: two fatal null reference_no crashes and a main-document gate that made drafts permanently unsavable.
10. Traced the partner indexing fully — the modal path is 1-based by design (`#partner-0` is an anchor), while the fallback serialiser was 0-based; `deletePartner()` only hid rows, so deleted partners still submitted.
11. Reordered all 12 `putFileAs` calls to write locally first with MinIO as best-effort inside try/catch, and found `File($path)` called as an undefined function — a production-only fatal.
12. Extended `/minio-check` with letter-image host probes, using hosts extracted from production data: `nilams.uitm.edu.my` (6764 refs) and `cdn.uitm.edu.my` (3479 refs).

### Key Insights & Learning
- A validation gate placed before a draft/submit branch silently converts "save as draft" into a full submission — the bug is in the ordering, not the rules.
- Relaxing validation at creation shifts the burden downstream: `store()` had been masking missing rules in `update()`, and only Fendy's question revealed it.
- Fixing one bug can invalidate the correct fix for another. Making `deletePartner` actually remove rows made gaps possible, which turned the previously correct fixed-index lookup into the wrong answer.
- `disabled` on a form field is an authorization decision in disguise: a disabled `document_category_id` on edit meant a category-less draft could never be repaired.
- `move()` consumes the uploaded temp file, so any post-move upload must read from the moved path.
- The `tbl_` prefix on the mysql connection cost two failed queries before it was noticed — configuration should be read before concluding a table is missing.

### Collaboration Highlights

- His question about resumed drafts caught a real validation gap that the implementation had opened and would not have surfaced in testing.
- The decision on draft-required fields was left to him; when the disabled edit field made "name only" unworkable, the constraint was surfaced rather than silently overridden — and later resolved properly by unlocking the field.

### Key Insights & Learning
- **`grep` in this shell is a function that respects `.gitignore`.** Because `login/config.php` and `login/login.php` were both listed there, every recursive grep this session silently skipped them. Conclusions happened to hold — both files had been read directly — but the survey was redone with `find -exec command grep` before any claim was restated. Worth remembering for this and every repo.
- **A verification that cannot fail proves nothing.** `git check-ignore` skips tracked files, so it reported "NOT ignored" for a file that *was* still listed. `--no-index` tests the rule itself. The first check was reported, then corrected.

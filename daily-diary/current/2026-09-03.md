### Key Insights & Learning
- **`mystudentlog` holds one document per student, not one per visit.** Every number the dashboard reports is therefore a count of *students*, not page views, and a student who checked five times appears once on their last date. The labels were written to say so — "Jumlah Pelajar", "tarikh paparan terakhir mereka" — rather than letting the chart imply traffic it cannot measure.
- A field written only at login sits next to a field written months later on the same document. `loggedIn` beside `viewResultAt` looks like one event and is not. Naming the chart "Kaedah Log Masuk **Terakhir**" was the honest fix; there is no way to recover per-view attribution from this shape.
- The intuitive colour choice was the wrong one, and only the validator caught it. Green-vs-red for can-view/blocked is what everyone reaches for, and it is the classic deutan collision — 4.1 against a floor of 8. Running the script cost seconds; reasoning about it would have shipped the bug.
- `getCountFromServer` bills per 1000 matched index entries, so the honest saving is about **330×** on a 50k-student range (~150 reads vs 50,000), not the ~1000× first quoted. The per-query ceiling is not the per-dashboard number.
- An equality filter plus a range on a different field needs a composite index — but one index serves *every* value of that equality field, so eight filtered counts needed only two indexes, not eight.
- `firebase deploy --only firestore:indexes` treats the local file as desired state and offers to delete anything missing from it. Pulling the live indexes first and copying them verbatim is what made the dry run propose zero deletions.
- html2canvas cannot rasterise `backdrop-filter`, so the glass cards would have exported as flat grey. `window.print()` with a print stylesheet was both the cheaper and the better-looking answer — and without `print-color-adjust: exact`, browsers strip background colours and the charts print blank.

### Main Topics Discussed
1. **nilams.es down locally (500).** The ServBay update moved every vhost to the default PHP, now 8.4. Laravel 8.83 with Carbon 2.72 fails on 8.4: deprecation warnings get logged while Carbon is still loading, Telescope calls `now()`, which needs Carbon, and the loop ends in `Class "Carbon\Carbon" not found`. Verified that PHP 8.3 boots fine. Fix: set the site (or the ServBay default) back to PHP 8.3.
2. **9430 (PIC didn't attach the documents).** The vetter should use **Upload Document** with a comment only (no file, final-draft box unticked). That sets `return-for-amendment` and opens the PIC's missing-attachments panel. "Return to Applicant" is really `decline-by-la`: it sends a "Declined" email and the application has to be resubmitted through the LA. It has worked that way since `0d14db8` (Mar 2022).
3. **8479 endorsement 500.** Telescope showed `Attempt to read property "jabatan" on null` in `vettings/letter.blade.php` (4 occurrences, vetter Adlin, user 27). The creator, Aznur Umiza (user 184, staff 161994), was soft-deleted on 8 Dec 2025 through the Users admin page. Nothing records who deleted her. `createdBy` returns an empty default model, so there's no department code, no jabatan, and the view crashes.
4. **Fendy changed the Created By** on 8479 through Manage Legal Documents. `insertUserLDAP` uses `updateOrCreate`, which ignores soft-deleted users, so it created a **duplicate user 3219** for the same staff no. It didn't set `department_code` (it works the value out but never saves it), so the same crash happened. Fendy then set 3219's code to A0402. The letter view now renders (checked locally as the vetter against live data).

### Key Insights & Learning
- Soft-deleting a user quietly breaks every `createdBy->...` chain. `withDefault()` hides the problem until the letter view reads a property on a null jabatan.
- `updateOrCreate` combined with soft deletes creates duplicate users. Any staff-number lookup needs `withTrashed()` and a restore.
- A plain `select()` on a list query silently drops columns that the per-row display logic depends on. Check what the row closures read.
- The menu labels in the LPU sidebar don't match the page titles, which is the main source of "it doesn't show there" reports.
